RAG Systems

Two Retrieval-Augmented Generation systems built around the same core pipeline: a document is ingested and split into chunks, embeddings are generated for each chunk and stored in a vector database, and when a user queries the document, the relevant chunks are retrieved and used to generate a grounded response.

RAAS

A team project built with 11 members. My role was to develop and manage the AI Gateway and the Chunking microservice, and to deploy the system to the staging environment along with its CI/CD pipeline.

The AI Gateway is the sole entry point through which any external AI service is called — chunking, embedding, reranking, LLM, ASR, TTS, OCR, or any other service. It holds a wrapper for each service that reformats the outgoing request the way that service expects, and reformats the response back into the format the rest of the system expects.

Key Responsibilities

  • Developed and managed the AI Gateway, the single routing point through which every request to an AI service passes
  • Built per-service wrappers in the gateway to format outgoing requests and normalize responses for chunking, embedding, reranking, LLM, ASR, TTS, OCR, and other services
  • Developed the Chunking microservice
  • Deployed the system to the staging environment
  • Set up the CI/CD pipeline for staging deployments

RAGKIT

A retrieval-augmented generation platform that answers questions from a private document collection with citations pointing to the exact source text. The pipeline combines dense vector search with BM25, fuses the two rankings, and reranks with a cross-encoder before generating an answer, and runs either as a single process or as a four-service container stack from the same codebase.

Key Responsibilities

  • Designed the system as four services — AI, file management, retrieval, and an API gateway — communicating only through typed protocols, so the same codebase deploys as one process or as containers with no change to application code
  • Enforced the service boundaries with nine import-linter contracts checked in CI, which caught two dependency violations that had passed code review
  • Implemented hybrid retrieval combining dense vector search and BM25 through Reciprocal Rank Fusion, followed by cross-encoder reranking
  • Improved retrieval accuracy from 0.95 to 1.00 hit@1 and 0.976 to 1.000 MRR by adding the reranking stage
  • Built two chunking strategies, recursive and hierarchical, where only child chunks are embedded and parent chunks supply wider context at prompt time
  • Built an evaluation harness over a 21-question golden set measuring hit@k, MRR, nDCG and latency percentiles for each retrieval configuration
  • Calibrated the refusal threshold from measured score distributions after an initial intuition-based value caused false refusals on 10% of answerable questions
  • Reduced off-topic query latency from roughly 102s to 993ms by refusing before generation instead of calling the language model
  • Cut the cost of adding a document to a second knowledge base from a full parse, chunk and embed cycle down to a single database row by keying chunk sets to file, strategy, parameters and embedder
  • Replaced a message broker with a PostgreSQL job queue using FOR UPDATE SKIP LOCKED and lease-based crash recovery, keeping asynchronous ingestion without an extra operational dependency
  • Wrote 276 unit and contract tests plus 51 integration tests against a real PostgreSQL instance, with strict type checking across 117 source files
  • Containerised the full stack — four services, a web UI, PostgreSQL, MinIO and Qdrant — behind a single multi-stage Dockerfile with health-gated startup ordering

RAG Chat

A solo project built as a basic demo system, with every part of the pipeline made swappable. The vector database can be Chroma, Milvus, or others; the LLM can be served through Ollama, HuggingFace, or any external API; and the embedding model and reranker are similarly interchangeable. The system parses an uploaded document and answers queries against it.

Key Responsibilities

  • Built a modular RAG pipeline with swappable vector store (Chroma, Milvus, or others), LLM provider (Ollama, HuggingFace, or any API), embedding model, and reranker
  • Implemented document ingestion and parsing, chunking, and embedding generation
  • Implemented query-time retrieval and response generation over the ingested document
  • Built solo, end to end, as a demo of the pipeline
